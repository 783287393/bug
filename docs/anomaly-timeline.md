# 受控异常实验时间线与分析

> 实验纪律：负载脚本仅请求本机 `127.0.0.1:8000`，限制并发与总次数；禁止压测非本人或未授权系统。
> 下表时间在实际运行后填写；曲线截图存入 `docs/evidence/`，编号与 PPT 截图清单一致。

## 实验一：受控加压（背景流量上涨）

|---|---|
| 开始时间 | 运行负载脚本前记录（示例：__:__） |
| 结束时间 | 脚本执行完成后记录（示例：__:__） |
| 动作 | `python scripts/load_test.py --total 200 --concurrency 4 --delay-ms 0` |
| 现象 | 请求速率上升，应用 CPU 小幅抬升；无 5xx，p95 基本平稳 |
| 曲线变化 | 请求速率曲线在加压时段出现峰值后回落；内存短期波动后回落 |
| 结论边界 | 只能说明「加压期间流量与资源随之变化」；仅凭现有指标不能定位具体慢代码或线程瓶颈 |

| 现象 | `up` 变为 0，`AppInstanceDown` 由 Pending 进入 Firing；恢复后回到 Resolved |
| 曲线变化 | 请求速率与延迟曲线在停机段无新样本；CPU、内存停止更新；恢复后曲线接续 |
| 结论边界 | 指标只能证明「抓取失败/进程不可达」，不能区分进程崩溃、端口占用还是机器关机；需结合进程日志与端口检查 |

## 诊断记录要点

1. 每条结论必须对应到具体 PromQL、时间窗口与标签来源。
2. 明确指出现有指标无法证明的内容（如根因定位、代码级瓶颈）。
3. 告警抖动时核对阈值基线、`for` 持续时间与窗口长度，不用一次尖峰触发告警。
